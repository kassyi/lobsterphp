# 言語・記述ルール

- 回答言語: 実装の解説、Walkthrough、Q&A、思考過程などはすべて日本語で行ってください。
- コメント: `// ★ FIX`や`// 修正箇所`などの変更箇所を明示する目的のコメントは決して書かないでください。
- クリーンなコード: 常にリファクタリングを意識し、読みやすく保守性の高いコードを維持してください。リファクタリングが必要であればアクションの最後にリファクタリングを私に提案してください。

# ファイル・パス運用ルール

環境の整合性を保つため、以下のパス指定を厳守してください。

- テスト中の出力物は`test\output`フォルダに出力してください。
- テスト用データは`test\integration_test_data`フォルダーにあります。
- 一時ファイル: いかなる理由があってもルートフォルダーに一時ファイルを出力してはなりません。一時的な出力が必要な場合は、必ず`ai_tmp/`フォルダーを使用してください。

# テスト運用ルール

- `tests/RendererTest.php` は、Markdownの解析およびレンダリング（見出し、リスト、テーブル等の各種要素や記法）に関する包括的な「キャラクターライゼーション・テスト」として機能しています。
- そのため、描画・レンダリングに関わる部分に対するリファクタリングを実施する際、同ファイル内ですでにテストがカバーされていると判断できる場合は、再度のテスト拡充をスキップし、このテストファイル群のパス (Green) をもって安全性を担保してよいものとします。
