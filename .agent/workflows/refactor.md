# Antigravity Workflow: AI自律型リファクタリング・プロトコル

このワークフローは、AIエージェントが**「自ら診察し、執刀する」**ための標準手順を定義したものです。巨大なファイルを無闇に読み込ませる旧来のやり方を捨て、データに基づいたピンポイントな改善を実現します。

---

## 1. フェーズ1：プロジェクトのCTスキャン (Diagnosis)

AIエージェントはまず、プロジェクトの全体像を把握するために以下のコマンドを実行します。

* **実行コマンド:** `../../utils/agency_gatekeeper.ps1 > .\ai_tmp\refactor.json`
* **AIの行動:** - 出力された統合JSONをパースする。
* `ScssDepth` でネストが深い（4階層以上）ファイルをリストアップする。
* `Complexity` で循環的複雑度が高い「スパゲッティ・メソッド」を特定する。
* `Assets` から、変数化すべき「マジックカラー/数値」の重複を確認する。



## 2. フェーズ2：戦略的優先順位の策定 (Strategic Planning)

取得したデータを元に、AIは「Why（なぜそこを直すのか）」に基づいた優先順位を決定します。

* **判断基準:**
1. **保守性リスク:** 複雑度スコアが20を超え、かつ頻繁に変更されるファイル。
2. **構造的欠陥:** SCSSのネストが深く、Bloggerテーマなどの表示崩れの原因になりやすい箇所。
3. **共通資産の漏れ:** 10箇所以上で直書きされている色設定。


* **成果物:** AIによる「リファクタリング・ロードマップ（TOP 3）」の提示。

## 3. フェーズ3：ターゲットの局所抽出 (Context Distillation)

AIは修正対象に選んだファイルに対し、いきなり全文を要求せず、まずは構造を再確認します。

* **実行コマンド:** `.\tools\Get-Interfaces.ps1 -Ext <対象拡張子>`
* **AIの行動:** - メソッドのシグネチャを確認し、影響範囲（依存関係）を特定する。
* 必要な行範囲（Line Range）だけをユーザーに要求し、読み込むトークン量を最小化する。

## 4. フェーズ4：戦略的仮説検証と飛躍的リファクタリングの実行 (Execution)

ターゲットを絞り込んだ状態で、AIは以下のリファクタリング案を提示します。

* **仮説検証型プロトコルの必須実行:** AIは修正案を提示する前に、「この修正を行うことで `ComplexityHeatmap` のスコアが X から Y に改善されるはずだ」という予測値を提示しなければなりません。これにより「構造的負債の解消」という目的との論理的整合性を担保します。
* **SCSS:** ネストを解除し、変数を用いたフラットな構造への変換。
* **TypeScript/C#:** 高負荷なロジックの分離、未使用エクスポートの削除。
* **成果物の検証:** 修正後のコードが `agency_gatekeeper.ps1` の再スキャンによって「スコア改善」したことをデータで証明する。
