# Antigravity Workflow: AI自律型汎用リファクタリング・プロトコル

このワークフローは、対象のプログラミング言語やフレームワークを問わず、AIエージェントが **「自ら診察し、執刀する」** ための標準手順を定義したものです。巨大なファイルを無闇に読み込ませる旧来のやり方を捨て、データに基づいたピンポイントな改善を実現します。

---

## 1. フェーズ1：プロジェクトのCTスキャン (Diagnosis)

AIエージェントはまず、プロジェクトの全体像を把握するために以下のコマンドを実行します。

- **実行コマンド:** `../../utils/agency_gatekeeper.ps1 > .\ai_tmp\refactor.json`
- **AIの行動:**
  - 出力された統合JSONをパースする。
  - `Depth/Nesting` 系の指標で、ネストが深すぎる（条件分岐、ループ、UI階層など）ファイルをリストアップする。
  - `Complexity` 系の指標で、循環的複雑度が高い「スパゲッティ・コード（関数/メソッド）」を特定する。
  - `Assets/Duplication` 系の指標から、定数化・共通化すべき「マジックナンバー / ハードコードされた文字列や値」の重複を確認する。

## 2. フェーズ2：戦略的優先順位の策定 (Strategic Planning)

取得したデータを元に、AIは「Why（なぜそこを直すのか）」に基づいた優先順位を決定します。

- **判断基準:**
  1. **保守性リスク:** 複雑度スコアが特定の閾値（例: 20）を超え、かつシステムの中核を担う、あるいは頻繁に変更されるファイル。
  2. **構造的欠陥:** ネストが深く、バグの温床やパフォーマンス・可読性悪化の原因になりやすい箇所。
  3. **共通資産の漏れ:** 複数箇所で直書きされている設定値（数値、色、URLエンドポイントなど）の散在。

- **成果物:** 検出された課題を重要度（Critical / High / Medium等）で分類した「段階的リファクタリング・ロードマップ」の提示。
  - _運用ルール:_ 課題が多数に上る場合、AIは一度に全ての修正を試みるのではなく、品質の維持とコンテキストウィンドウの制約を考慮し、「フェーズ1（今週のSprint）」「フェーズ2（次回のSprint）」のようにタスクを管理可能な単位に分割して提案しなければならない。

## 3. フェーズ3：ターゲットの局所抽出 (Context Distillation)

AIは修正対象に選んだファイルに対し、いきなり全文を要求せず、まずは構造を再確認します。

- **実行コマンド:** `.\tools\Get-Interfaces.ps1 -Ext <対象拡張子>` （またはそれに準ずる定義抽出ツール）
- **AIの行動:**
  - クラス、関数、モジュールのシグネチャを確認し、影響範囲（依存関係）を特定する。
  - 必要な行範囲（Line Range）だけをユーザーに要求し、読み込むトークン量を最小化する。

## 4. フェーズ4：戦略的仮説検証と飛躍的リファクタリングの実行 (Execution)

ターゲットを絞り込んだ状態で、AIは以下のリファクタリング案を提示します。

- **仮説検証型プロトコルの必須実行:** AIは修正案を提示する前に、「この修正を行うことで各種メトリクス（複雑度やネスト深度など）のスコアが X から Y に改善されるはずだ」という予測値を提示しなければなりません。これにより「構造的負債の解消」という目的との論理的整合性を担保します。
- **プレゼンテーション/UI層:** ネストや依存関係を整理し、変数やコンポーネントを用いたフラットで再利用可能な構造への変換。
- **ロジック/バックエンド層:** 肥大化した関数・メソッドの分割、単一責任の原則（SRP）の徹底、未使用シンボル（Orphans）の削除。

## 5. フェーズ5：振る舞いの不変性保証 (Regression Testing)

リファクタリングの定義である「外部から見た振る舞いを変えないこと」を厳格に担保します。

- **テストの実行義務:** AIはフェーズ4の修正完了後、既存のテストスイート（例: PHPUnit, Jestなど）を実行し、変更前後でテストが全てパス（グリーン）であることを証明しなければならない。
- **テストがない場合の防御策:** 対象のコードにテストが存在しない（カバレッジツール等で `hasTest: false` と判定された）場合、AIはリファクタリングを行う **前** に、現在の振る舞いを固定するための「キャラクターライゼーション・テスト（現状確認テスト）」の作成を最優先で提案し、実行しなければならない。
